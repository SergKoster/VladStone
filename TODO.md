# VladStone Roadmap

Roadmap хранит будущие цели в порядке, в котором их разумно делать. Уже реализованные вещи не дублируем, чтобы файл оставался рабочим планом, а не архивом.

## Принципы

- Сервер остается авторитетным источником правды для боя, коллекции, экономики, наград и прогресса.
- Клиент отправляет намерения игрока, а не готовое состояние игры.
- Realtime, таймеры и reconnect закладываем до PvP, а не после него.
- Боевые правила развиваем отдельно от UI, auth, коллекции и экономики.
- Анимации строятся по серверным combat events, а не угадываются фронтом.
- Сначала делаем понятную механику и расширяемую архитектуру, потом визуальный стиль, арты и тяжелый polish.
- Без лутбоксов. Получение карт должно быть детерминированным или через явно описанные награды/ивенты.
- Проект должен быть готов к web, а позже к desktop/mobile без переписывания backend.

## 2. UX Боя Без Финального Арта

- [ ] Переработать layout боя: поле боя и панель управления занимают всю высоту окна.
- [ ] Сделать поле боя центральной частью экрана, а не маленьким блоком в углу.
- [ ] Зафиксировать размеры клеток и панели так, чтобы интерфейс не прыгал от текста, юнитов и логов.
- [ ] Сделать responsive-режим для узких экранов: поле сверху, управление снизу или в компактной боковой панели.
- [ ] Упростить боевой лог: оставить полезный debug-лог отдельно, а игроку показывать короткие понятные события.
- [ ] Добавить понятное состояние `идет резолв хода`, при котором кнопки заблокированы, но поле остается читаемым.
- [ ] Сделать result overlay стабильным: победа/поражение, награда, кнопка нового боя, выход на главную.

## 3. Animation Layer Боя

- [ ] Добавить очередь проигрывания combat events.
- [ ] Сделать плавное перемещение юнитов с одного тайла на другой, чтобы путь был виден глазами.
- [ ] Добавить анимацию удара: атакующий юнит резко прыгает к цели и возвращается обратно.
- [ ] Добавить всплывающий красный текст урона над целью: например `-1`, `-2`.
- [ ] Добавить анимацию столкновения: два юнита одновременно прыгают в целевую клетку с двух сторон и отлетают назад.
- [ ] Синхронизировать длительность анимаций с micro-step событиями, чтобы игрок понимал, кто и почему сработал.
- [ ] Добавить настройку скорости анимаций для тестов баланса: медленно, нормально, быстро.
- [ ] Добавить fallback без анимаций для debug и будущих автотестов.
- [ ] Поддержать reduced motion.

## 4. Карты, Колода И Тестовый Баланс

- [ ] Убрать дублирование тестовых карт между frontend и backend: frontend должен получать card catalog с API.
- [ ] Добавить endpoint каталога карт.
- [ ] Добавить модель колоды игрока.
- [ ] Добавить deck builder для тестовой колоды.
- [ ] Ввести 4 карты в колоде и 4 карты на руке как серверную модель, а не frontend-заглушку.
- [ ] Подготовить draw/discard модель, даже если цикл добора пока отключен.
- [ ] Добавить первые дополнительные тестовые карты только после стабилизации текущих двух.
- [ ] Добавить балансные тесты/сценарии: спам дальников, толстяк против дальника, пустая линия, герой под атакой.

## 5. PvP Invite Prototype

- [ ] Спроектировать модель участников матча: player A, player B, bot, spectator позже.
- [ ] Добавить invite match flow: создать приглашение, открыть по ссылке, присоединиться вторым игроком.
- [ ] Использовать уже готовый WebSocket match channel для синхронизации двух клиентов.
- [ ] Синхронизировать planning phase между двумя клиентами.
- [ ] Серверно завершать ход по таймеру, даже если один или оба клиента молчат.
- [ ] Поддержать тест с двух вкладок и двух устройств.
- [ ] Добавить reconnect в PvP-матч.
- [ ] Добавить базовые правила отмены/поражения при выходе игрока.
- [ ] Добавить режим PvP с выровненными возвышениями карт ради баланса.

## 6. Экономика И Коллекция

- [ ] Описать источники получения карт без лутбоксов: задания, ивенты, milestone, крафт, прямые награды.
- [ ] Добавить журнал выдачи наград игроку.
- [ ] Добавить атомарную выдачу лимитированных карт с счетчиком `получено/лимит`.
- [ ] Добавить защиту от двойной выдачи лимитированной награды.
- [ ] Расширить возвышение карт до 3 ступеней: `Дефолт`, `Возвышенный`, `Возвышенный+`.
- [ ] Решить, что именно дает возвышение: новая способность, альтернативное поведение или косметика.
- [ ] Добавить страницу деталей карты.

## 7. Production Auth И Email

- [ ] Подключить реальную отправку email-кодов через выбранный email provider.
- [ ] Добавить production-safe Google OAuth flow.
- [ ] Описать правила линковки email и Google аккаунтов.
- [ ] Добавить CSRF-стратегию для cookie-based refresh flow.
- [ ] Добавить список активных сессий/устройств.
- [ ] Добавить отзыв refresh-сессии с конкретного устройства.

## 8. CI, Деплой И Эксплуатация

- [ ] Добавить GitHub Actions: backend tests, ruff, frontend build.
- [ ] Сделать отдельный production compose или deploy docs.
- [ ] Разделить `.env.example` и реальные `.env` сценарии для local/staging/prod.
- [ ] Настроить production CORS под конкретный домен.
- [ ] Добавить healthcheck для API, PostgreSQL и Redis в deploy-документацию.
- [ ] Настроить миграции как явный шаг деплоя.
- [ ] Добавить backup/restore план для PostgreSQL.
- [ ] Добавить structured logging для backend.
- [ ] Добавить Sentry или другой error tracking для frontend/backend.
- [ ] Подготовить multi-instance план: API replicas, Redis pub/sub для realtime, sticky sessions или stateless WS gateway.

## 9. Pre-Release Polish И Уведомления

- [ ] Провести архитектурный аудит перед анонсом друзьям: границы модулей, зависимости, realtime, хранение, тесты, deploy path.
- [ ] Добавить отображение ping/latency в бою и debug-панели.
- [ ] Добавить понятный индикатор нестабильного соединения: reconnect, высокий ping, потеря WebSocket, fallback на polling.
- [ ] Добавить историю завершенных матчей, чтобы игрок видел результат, если матч дорезолвился без него.
- [ ] Добавить систему уведомлений внутри игры: `матч завершился`, `получена награда`, `истек ход`.
- [ ] Позже подключить email/push-уведомления для важных событий, если игрок был офлайн.
- [ ] Сделать экран получения награды после офлайн-завершения матча.
- [ ] Проверить UX первого тестового запуска для друзей: вход, старт боя, reconnect, награда, понятные ошибки.

## 10. MMO-Слой После Стабильного Боя

- [ ] Спроектировать карту мира как отдельный feature-модуль, не связанный напрямую с боевым UI.
- [ ] Добавить события/ивенты как серверные сущности.
- [ ] Добавить участие игрока в ивенте и event reward track.
- [ ] Добавить массовые цели без прямого соревновательного давления.
- [ ] Добавить магазин/крафт только после ясной экономики без pay-to-win.
- [ ] Подготовить систему эксклюзивных и лимитированных карт с audit trail.
- [ ] Использовать realtime foundation для массовых событий, а не городить отдельный канал с нуля.

## 11. Платформы И Polish

- [ ] PWA-режим для web.
- [ ] Desktop wrapper: Tauri или Electron после стабилизации web-клиента.
- [ ] Mobile strategy: Capacitor, React Native или отдельный клиент после проверки web-фундамента.
- [ ] Звуки боя и UI.
- [ ] Финальный визуальный стиль карт.
- [ ] Пайплайн ассетов карт и косметики.
- [ ] Accessibility-настройки: скорость анимаций, reduced motion, читаемые размеры текста.
