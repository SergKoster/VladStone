# Модуль 1. Современный Python для бэкенда

> База всего бэкенда. Цель — читать любой файл `VladStoneAPI/` без «что это за
> синтаксис?» и понимать, как устроено окружение проекта.

## Что нужно знать на выходе

- Типизация: аннотации, `Optional`/`| None`, дженерики, `TypedDict`,
  `Protocol`, зачем типы в языке без строгой типизации.
- Датаклассы и их отличие от Pydantic-моделей (у нас везде Pydantic — почему).
- `asyncio`: event loop, `async`/`await`, задачи (`create_task`), почему один
  поток обслуживает сотни соединений и когда это ломается (блокирующий код).
- Пакеты и окружение: `venv`, `pip`, `pyproject.toml`, чем dev-зависимости
  отличаются от прод-зависимостей.
- Идиомы: генераторы, comprehension, контекстные менеджеры (`with`),
  декораторы (FastAPI на них построен), исключения и их иерархия.

## Ресурсы

1. [Официальный туториал Python](https://docs.python.org/3/tutorial/) — если
   есть пробелы в базе; иначе пропустить.
2. [Документация typing](https://docs.python.org/3/library/typing.html) +
   [cheat sheet от mypy](https://mypy.readthedocs.io/en/stable/cheat_sheet_py3.html) —
   типизация, главный «новый» навык.
3. [Real Python: Async IO in Python](https://realpython.com/async-io-python/) —
   лучший разбор asyncio для начинающих (англ.).
4. Книга **«Fluent Python» (Лучано Рамальо), 2-е издание** — читать выборочно:
   главы про модель данных, функции, декораторы, асинхронность. Это книга
   уровня «профессиональный разработчик», можно растянуть на весь план.
5. [Хабр: подборка ресурсов Python](https://habr.com/ru/companies/yandex_praktikum/articles/750048/) —
   русскоязычные дополнения по вкусу.

## Где это у нас

- `VladStoneAPI/pyproject.toml` — зависимости, настройки pytest и ruff.
  Разобрать каждую строку: что делает пакет, почему он тут.
- `VladStoneAPI/app/domain/combat/engine/` — чистый Python без фреймворков:
  Pydantic-модели, enum'ы, типизация. Идеальное место читать «просто Python».
- `VladStoneAPI/app/services/combat_timer_worker.py` — живой asyncio: фоновая
  задача в lifespan, тик раз в секунду, обработка исключений, чтобы тик не
  умирал.
- `.venv` — виртуальное окружение; понять, почему команды запускаются как
  `.\.venv\Scripts\python -m ...`.

## Практика

1. Открыть `engine/models` (модели движка) и выписать все конструкции
   типизации, которые встретились; для каждой объяснить (себе или Claude),
   что она значит.
2. Написать в песочнице (отдельный файл вне проекта) маленький asyncio-скрипт:
   две конкурентные задачи, одна «тикает» раз в секунду, вторая по команде
   останавливает первую. Это ровно схема нашего таймер-воркера.
3. Найти в `combat_timer_worker.py` место, где исключение одного матча не
   роняет весь тик, и объяснить, почему это важно (см. ARCHITECTURE §8.14).
4. Создать с нуля пустой venv, поставить в него fastapi и uvicorn, поднять
   «hello world» из одного файла. Убедиться, что понимаешь каждый шаг.
