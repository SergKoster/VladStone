# Модуль 6. Тестирование и качество кода

> У проекта уже есть pytest-сьют, ruff и CI. Цель — уметь читать и писать
> тесты всех наших видов и понимать, что именно каждый вид гарантирует.

## Что нужно знать на выходе

- pytest: устройство теста, фикстуры, параметризация, `conftest.py`,
  маркеры, как запускать подмножества тестов.
- Виды тестов у нас: чистые доменные (движок боя без I/O), API-тесты через
  `TestClient` (HTTP без реального сервера), регрессионные на гонки.
- Почему чистый домен (инвариант ARCHITECTURE §4.6) — это прежде всего
  **тестируемость**: бой прогоняется без БД и сети.
- Линтер ruff: какие классы ошибок ловит (наш набор: E, F, I, UP, B), чем
  линтер отличается от форматтера и от тайпчекера.
- CI: что делает `.github/workflows/ci.yml` на каждый push и зачем.

## Ресурсы

1. [Документация pytest: Getting Started + How-to](https://docs.pytest.org/en/stable/) —
   основной ресурс; разделы fixtures и parametrize обязательны.
2. Книга **Brian Okken, «Python Testing with pytest» (2-е изд.)** — лучший
   системный учебник по pytest; русский перевод: «Изучаем pytest»
   ([ЛитРес](https://www.litres.ru/book/aleks-kogan/izuchaem-pytest-ot-osnov-do-prodvinutyh-tehnik-testirovaniya-v-73988369/) —
   аналогичная по охвату книга Когана).
3. [Stepik: Pytest для Python-разработчиков](https://stepik.org/course/259625/promo) —
   бесплатный русскоязычный курс с задачами.
4. [FastAPI: Testing](https://fastapi.tiangolo.com/tutorial/testing/) — как
   тестировать роуты через `TestClient`.
5. [Документация ruff](https://docs.astral.sh/ruff/) — обзор правил.

## Где это у нас

- `VladStoneAPI/tests/` — весь сьют. Ключевые файлы для чтения:
  - `test_engine_extensions.py` — чистые доменные тесты движка v4;
  - `test_combat_api.py` — API-тесты (включая гейт версий правил);
  - `test_combat_resolve_race.py` — регрессия на гонку резолва;
  - `conftest.py` — общие фикстуры (как поднимается тестовая БД/клиент).
- `pyproject.toml` — секции `[tool.pytest.ini_options]` и `[tool.ruff]`.
- `.github/workflows/ci.yml` — пайплайн: pytest + ruff + npm build.

## Практика

1. Запустить весь сьют (`.\.venv\Scripts\python -m pytest`), затем один файл,
   затем один тест по имени (`-k`). Посмотреть на вывод падающего теста —
   сломать что-нибудь нарочно в песочной ветке.
2. Прочитать `conftest.py` и объяснить: откуда в API-тестах берётся БД и
   почему тесты не портят dev-базу.
3. Написать свой доменный тест: любой простой сценарий движка (например,
   «юнит с ядом теряет 1 HP на тике»), по образцу соседних тестов.
4. Прогнать ruff, затем нарочно нарушить правило (неиспользуемый импорт,
   неотсортированные импорты) и посмотреть, что он скажет.
5. Открыть последний прогон CI на GitHub (вкладка Actions) и сопоставить шаги
   с ci.yml.

## Вопросы для самопроверки

- Что такое фикстура и чем она лучше «setup в начале каждого теста»?
- Почему доменные тесты движка не требуют БД, а API-тесты — требуют? Что
  каждый вид ловит такого, чего не ловит другой?
- Тест на гонку резолва: как в тесте вообще воспроизводится «одновременность»?
- Что упадёт раньше при кривом коде: ruff, pytest или ревью — и почему CI
  гоняет всё вместе?
