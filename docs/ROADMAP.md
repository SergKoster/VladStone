# VladStone — Roadmap

> Двухэтапный релиз (решение владельца, R1): **Релиз 1 «Для друзей»** — цель
> сентябрь 2026; **Релиз 2 «Публичный MMO»** — без даты. Скоуп релизов:
> [DESIGN.md](DESIGN.md) §11. Технические детали фаз: [ARCHITECTURE.md](ARCHITECTURE.md) §5.
> Фазы упорядочены по зависимостям; внутри фазы порядок свободный.
> Мелкие задачи и баги — в [TODO.md](../TODO.md).

> **Актуальный срез на 15 июля 2026:** P0–P2 боёвки v4 закрыты; live-путь уже
> использует `RULESET_VERSION` 3, `engine/`, v4 API и `BattleV4` с покадровым
> replay. **Текущий этап — P3: довести контент, баланс и UX v4 до плейтеста.**
> Следом P4: задеплоить друзьям, собрать фидбек и зафиксировать O10. До P4
> обязательны release blockers ниже; deck builder/коллекция идут параллельной
> Фазой 3, но сначала нужен единый v4-каталог.

### Сквозные release blockers до первого внешнего деплоя (COMBAT P4)

- [ ] Свести коллекцию, стартовую выдачу и live-бой к одному v4-каталогу
      (ARCH §8.18).
- [ ] Закрыть анонимное создание/управление live-матчами и ограничить частоту
      start/resolve (ARCH §8.9).
- [ ] Выключить или ограничить dev telemetry в production (ARCH §8.10).
- [ ] Ввести лимит body и количества intents в combat/WS payload (ARCH §8.20).
- [ ] Изолировать медленные/сломанные WS-сокеты: per-connection queue,
      send-timeout и отключение при переполнении (ARCH §8.19).
- [ ] Проверять Google ID token библиотекой/JWKS: подпись, `aud`, `iss`, `exp`
      (ARCH §8.21).
- [ ] Зафиксировать воспроизводимый Python dependency set для CI и prod-образа
      (ARCH §8.22).

## Фаза 0 — Сделано (MVP боя)

Серверный бой с микроходами и фазовым резолвом, deck cycle (рука 3 / добор /
перетасовка, порядок — серверный секрет), 11 тестовых карт с артами и редкостями
(каталог — `domain/combat/cards.py`, все статы временно = 1), анимационный слой
по combat events (выпады, урон в момент удара, смерти, добор),
тосты ошибок на клетках, PvE-бот с детерминированным паттерном (лайны 0/1),
идемпотентные награды, dev-auth, CI (pytest+ruff+build), PWA-манифест,
эндшпиль таймера с буфером анимации.

## Релиз 1 — «Для друзей» (цель: сентябрь 2026)

### Фаза 1 — Боевое ядро 2.0

Цель: правила боя, на которых можно строить контент. **Порядок первых трёх
пунктов фиксирован** (решения R11–R13): плейтесты → модель участников →
движок способностей — чтобы не переписывать резолвер дважды.

- [x] 1. Первый плейтест старого ядра с владельцем и другом; фидбек привёл к
      канону v4 и решениям C1–C5/S1–S3 (июль 2026; PLAYTEST_NOTES,
      COMBAT_REWORK §19). Повторный широкий плейтест v4 — P4/O10.
- [x] 2. Модель участников: N игроков с командами, колода/рука per-player,
      убрать хардкод `"player"`/`"bot"` (R12, ARCH §5.2; перенесено из Фазы 4 —
      фундамент и для PvP, и для босса). **Сделано** (июль 2026,
      первоначально `RULESET_VERSION` 2; live после интеграции v4 — версия 3).
- [x] 3. Движок способностей: `card_type (unit|spell)`, `abilities` в CardDefinition,
      триггеры/хуки конвейера резолва, детерминированный порядок (ARCH §5.1);
      цикл хода и мана-расписание параметризуемы — эффекты «доп. ход» / «кража
      маны» входят в Р1 (R13). **Сделано** в `domain/combat/engine/` (июль 2026).
- [x] Статус-эффекты на юнитах и волновая модель триггеров/смертей.
- [x] Карты-заклинания с targeting-схемами.
- [x] Новые combat events + серверные снапшоты + покадровый replay A1–A6.
- [x] Эндшпиль: сжатие таймера и «суд» на ходу N вместо отменённого chip
      damage (DESIGN §3.5; число N остаётся балансной ручкой O10).
- [ ] Кнопка «сдаться» (concede).
- [x] Фоновый тикер дорезолва просроченных ходов (`combat_timer_worker.py`,
      тик 1 с + WS broadcast; ленивый дорезолв в роутах — подстраховка).

### Фаза 2 — Контент и баланс (зависит от Фазы 1)

### Фаза 3 — Колода и коллекция (параллельно Фазе 2)

- [ ] **P0 до любой работы над deck builder:** убрать split-brain каталога
      (ARCH §8.18). `/me/collection` и стартовая выдача сейчас читают мёртвый
      MVP-каталог, а бой — `engine/content.py`; игрок видит неверные статы/
      редкости и не видит весь v4-набор. Один v4-источник должен кормить
      коллекцию, выдачу, deck validation и бой.
- [ ] Модель PlayerDeck (12 карт, без дублей, серверная валидация).
- [ ] Deck builder UI (сборка из коллекции, активная колода).
- [ ] Старт матча с выбранной колодой.
- [ ] Отключить возвышение (UI + `/ascend`); коллекция = карта + количество (R9).
- [ ] Стартовый набор новичка: фиксированный набор 12+ карт в коллекцию при
      регистрации (R14); состав набора — решение владельца, когда карт хватит (O5).
