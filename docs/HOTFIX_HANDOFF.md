## 0. Железные правила (нарушение = регресс)

- **НЕ ТРОГАТЬ движок боя** `VladStoneAPI/app/domain/combat/engine/*` (кроме
  единственной точечной правки payload в задаче T3, строго по инструкции).
  Он покрыт 141 тестом и корректен. Любая правка правил боя ломает инварианты.
- **НЕ переписывать бэкенд-роуты, персистенс, WS** — они рабочие.
- **После КАЖДОЙ задачи гнать проверки:**
  - Бэкенд: из `VladStoneAPI/` — `.\.venv\Scripts\python -m pytest -q` (должно
    быть **141 passed**) и `.\.venv\Scripts\python -m ruff check .` (All checks
    passed).
  - Фронт: из `VladStoneWeb/` — `npm run build` (tsc+vite, без ошибок).
- **Проверка в браузере:** фронт и API на ОДНОМ хосте `127.0.0.1` (не
  `localhost`) — иначе куки авторизации отвалятся (401). Вход: кнопка «Войти
  через Google» (dev-login). **Скриншоты превью таймаутят во время боя —
  проверять DOM-семплингом** (`document.querySelectorAll`), не скриншотом.
- Предупреждения git про CRLF/LF — игнорировать, это норма Windows-репо.
- Затронутый экран — `VladStoneWeb/src/features/battle/BattleV4.tsx` (весь
  фронт боя тут, ~380 строк) + стили в `VladStoneWeb/src/styles.css` (блок
  «Боёвка v4» в конце).

## Контекст полезного (что уже есть)

Payload юнита от сервера (проверено live) содержит всё нужное для показа статов:
```
{ id, owner_id, side, blueprint_id, card_id|null, row, col,
  current_hp, max_hp, damage, stance, is_tower, statuses[], 
  remaining_steps, remaining_attacks }
```
Каталог карт (`GET /combat/catalog`, тип `CombatCatalogCard` в `api.ts`) содержит
`stats {hp, damage, attacks_per_turn, move_steps}`, `coverage_*`, `spawn_rows`.

## T2. Таймер >30 + авто-сабмит на дедлайне (баги B6, B5) — ПРОСТО/СРЕДНЕ

**B6 — таймер показывает 32/35/40+.** Причина: сервер добавляет «буфер на
анимацию» к дедлайну планирования, а анимаций во v4 больше нет → буфер стал
бессмысленным, но раздувает таймер.

Правка (обнулить буфер, механизм НЕ выпиливать — вернётся с анимациями):
- Файл `VladStoneAPI/app/domain/combat/engine/battle.py`, функция
  `_advance_turn_and_check_end`: строка `buffer = resolution_buffer_seconds(num_events)`
  → заменить на `buffer = 0` (или удалить прибавление buffer к дедлайну).
  Оставить импорт/функцию на месте (коммент: «буфер 0 — анимаций нет, вернуть
  при возврате покадровой анимации»).
- Подстраховка на клиенте: в `BattleV4.tsx` в расчёте `secondsLeft` капнуть
  показ: `Math.min(TURN_SECONDS, left)`.

**B5 — на 0 секунд «ничего не происходит».** Причина: нет клиентского
авто-сабмита; клиент ждёт серверный таймер-воркер. Правка в `BattleV4.tsx`:
когда `secondsLeft` доходит до 0 и статус `planning` и не `busy` — вызвать
`handleResolve()` ОДИН раз (флаг, чтобы не зациклить). Сервер всё равно
авторитетно дорезолвит если клиент опоздал (роут вернёт 409 → `catch`
рефетчит `getCombat` — уже реализовано).

Проверка бэкенда: pytest (тест дедлайна `test_deadline_resolves_by_timer_without_client`
должен остаться зелёным — буфер не влияет на факт резолва). Браузер: после хода
таймер стартует с 30, не выше; при простое ход резолвится сам.

## T3. Статы юнитов на поле (баги B1, S1) — СРЕДНЕ (бэкенд payload + фронт)

Симптом: юнит на поле показывает только HP; нужно как в MVP — HP, урон, шаги,
атаки. Плюс remaining-бюджеты «залипают» (сходивший показывает 0).

Причина: `UnitToken` в `BattleV4.tsx` рисует только арт+HP. И в payload юнита
нет БАЗОВЫХ move_steps/attacks_per_turn (есть только remaining — середина хода).

Правки:
1. **Бэкенд (единственная разрешённая точечная правка движка), файл
   `VladStoneAPI/app/domain/combat/engine/payload.py`, функция `_unit_payload`:**
   добавить в возвращаемый dict базовые статы из `effective_stats(unit, blueprint)`:
   `"move_steps": stats.move_steps, "attacks_per_turn": stats.attacks_per_turn`
   (`stats` там уже вычислен). НИЧЕГО больше в движке не трогать.
2. **Фронт `api.ts`**: в тип `CombatUnit` добавить `move_steps: number;
   attacks_per_turn: number;`.
3. **Фронт `BattleV4.tsx`, компонент `UnitToken`:** показать статы поверх/под
   артом — HP `current_hp/max_hp`, урон `damage`, шаги `move_steps`, атаки
   `attacks_per_turn`, стойка (иконка/цвет). Показывать БАЗОВЫЕ значения
   (не remaining) — их и добавили в payload. Стиль — компактные пилюли в углах
   токена (см. существующие `.unit-v4-hp`, добавить `.unit-v4-dmg` и т.п. в
   `styles.css`). Ориентир вида — как в старом MVP токене (иконки урон/шаги/
   атаки/HP).

Проверка: pytest (payload-тесты `test_engine_battle.py` /
`test_combat_api.py` должны пройти — добавление полей их не ломает, если не
удалять старые); `npm run build`; в бою у юнита видны все статы.

## T4. Drag-n-drop расстановки (баг B4) — РИСКОВАННО (мины ниже)

Симптом: карту нельзя перетащить на клетку, только клик-выбор → клик-клетка.
Сейчас в `BattleV4.tsx` реализован только клик-путь.

**ВНИМАНИЕ — известные мины (в MVP на них уже наступали, не повтори):**
- **Картинки перетаскиваемы браузером по умолчанию** → нативный drag арта
  глотает pointer-события. `CardArt` уже ставит `draggable={false}` — НЕ снимать;
  если добавляешь новые `<img>`, тоже `draggable={false}`.
- **Тач-скролл**: на элементах руки нужен `touch-action: none`, иначе тач-драг
  скроллит страницу.
- **Порог 6px** отличает тап-выбор от перетаскивания (иначе каждый тап
  превращается в драг). Сохранить оба пути: клик-выбор ДОЛЖЕН остаться рабочим.
- **Клетка под курсором** — через `document.elementFromPoint(x,y)` + атрибут
  `data-cell` (или data-row/col) на клетках; координаты мерить ЖИВЬЁМ на каждом
  pointermove (страница может скроллиться / сервер дорезолвит ход по таймеру,
  заранее снятые координаты устаревают → ложный «баг»).
- **pointer capture** на карте (`setPointerCapture`) чтобы move/up приходили
  после ухода курсора; в try/catch (синтетические указатели могут отклонить).
- Общий путь размещения — переиспользовать существующую логику `handleCellClick`/
  валидацию `isValidTarget` (те же проверки маны/зоны/занятости), не дублировать.

**Рекомендация:** если бюджета мало — этот пункт МОЖНО отложить (клик-путь
играбелен). Если делать — строго по минам выше, с проверкой руками на мыши И на
тач-эмуляции.

Проверка: перетащить карту, взявшись за арт → появляется ghost, клетка
подсвечивается, дроп ставит план; тап-выбор по-прежнему работает; на мобильной
ширине драг не скроллит.

## T5. Спелл в пустую клетку тратит ману (баг S2) — ПРОСТО

Симптом: спелл (Банка/Грибы/Задание) можно кинуть на пустую клетку — на сервере
он физзлится (нет цели-юнита), мана тратится впустую.

Правка в `BattleV4.tsx`, `isValidTarget`: для `card_type === "spell"` требовать,
чтобы в клетке был юнит (`unitAt(row,col)` не пуст) — либо подсвечивать только
такие клетки. (Наши 3 спелла все таргетят юнита. Спеллов на всё поле в контенте
нет.)

Проверка: спелл нельзя запланировать на пустую клетку; на юнита — можно.
